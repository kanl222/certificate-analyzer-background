# Изолированный фоновый контроль сертификатов

Этот каталог — самостоятельная реализация-прототип. Она **не подключена** к
основному CLI, GUI, bootstrap или установщикам проекта. Сервис только использует
уже существующие сервисы чтения БД, Excel-экспорта и системных уведомлений.

## Что делает процесс

- сразу после старта и затем через `check_interval_seconds` пересчитывает сроки
  всех сертификатов в БД приложения;
- при статусах `EXPIRED` и `EXPIRING_SOON` создаёт системное уведомление и
  сохраняет оповещение для чтения приложением через API;
- формирует XLSX-отчёт через `report_interval_seconds` (по умолчанию 7 суток);
- сохраняет дату следующего отчёта и историю оповещений, поэтому перезапуск не
  сдвигает недельный график;
- слушает только `127.0.0.1:8765` по умолчанию.

Порог «скоро истекает» берётся из `warning_days` основного файла настроек,
указанного в `application_config_path`.

Windows-службы работают в изолированной desktop-сессии, поэтому toast может не
быть виден вошедшему пользователю. Надёжный канал — `GET /v1/alerts`: GUI может
опросить его и показать уведомление самостоятельно. На Linux то же ограничение
возможно у системного systemd unit без пользовательской D-Bus-сессии.

## Конфигурация и локальный запуск

Скопируйте `runtime.example.json`, исправьте пути и запустите:

```text
python -m certificate_analyzer.runtime.codex --config C:\path\runtime.json
```

Относительные пути разрешаются от каталога `runtime.json`. Секрет API не
записывается в файл: задайте его в переменной, указанной в `api_token_env`.
Для loopback токен опционален; для любого сетевого адреса он обязателен.

## API для приложения

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/v1/health` | готовность процесса |
| `GET` | `/v1/status` | расписание, статистика и последние ошибки |
| `GET` | `/v1/certificates?status=EXPIRED&limit=100&offset=0` | последний снимок сертификатов |
| `GET` | `/v1/alerts?after_id=0` | новые оповещения для GUI |
| `GET` | `/v1/reports/latest` | последний созданный отчёт |
| `POST` | `/v1/checks` | внеочередная проверка |
| `POST` | `/v1/reports` | внеочередной отчёт |

Если токен настроен, передавайте `Authorization: Bearer <token>`. Готовый
stdlib-клиент находится в `client.py`; подключение его к GUI оставлено за
границами этой реализации.

## Linux (systemd)

Шаблон находится в `linux/certificate-analyzer-runtime.service`. Скопируйте его
в `/etc/systemd/system`, предварительно заменив `WorkingDirectory`, `ExecStart`
и путь к конфигурации. Затем администратор может выполнить:

```text
systemctl daemon-reload
systemctl enable --now certificate-analyzer-runtime.service
```

Для уведомлений в пользовательской сессии предпочтительнее user unit
(`systemctl --user`) или показ оповещений самим GUI через API.

## Windows Service

Нужна optional-зависимость проекта `windows` и абсолютный путь к конфигурации в
системной переменной `CERTIFICATE_ANALYZER_RUNTIME_CONFIG`. Из активированного
окружения с правами администратора:

```text
python -m certificate_analyzer.runtime.codex.windows_service install --startup auto
python -m certificate_analyzer.runtime.codex.windows_service start
```

Удаление выполняется явными командами `stop`, затем `remove`. Код ничего не
устанавливает и не регистрирует автоматически.
